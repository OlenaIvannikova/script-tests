# Functional test suites

## Suite 1: Input validation tests (проверка входных файлов и их форматов)

### users.txt

Позитивный сценарий: файл не пустой (содержит корректные логины), пустой файл, файл содержит дубликаты логинов
Негативный сценарий: файл отсутствует

### users.csv файл

1) Разделители ,
   Позитивный сценарий: корректный разделитель ,
   Негативный сценарий: любой другой разделитель

2) Первая колонка - login
   Позитивный сценарий: логин
   Негативный сценарий: логин отсутствует

3) Вторая колонка - email
   Позитивный сценарий: email корректного формата
   Негативный сценарий: email некорректного формата, email отсутствует

4) Позитивный сценарий: пустой файл

### users.json

Позитивный сценарий: содержит валидный JSON, пустой файл, пустой JSON-объект, JSON содержит дубликаты ключей
Негативный сценарий: невалидный JSON

# Suite 2: User data merging tests (логика объединения пользователей)

### Один логин пользователя

1) Есть во всех 3 файлах (txt, csv, json) -> пользователь добавляется в результат со всеми данными
2) Есть в 2 файлах (txt, csv), но нет json файле -> пользователь пропускается + понятное предупреждение
3) Есть в 2 файлах (txt, json), но нет в csv файле -> пользователь пропускается + понятное предупреждение
4) Есть только в файле txt -> пользователь пропускается + понятное предупреждение
5) Есть в файлах json и csv, но нет в файле txt -> пользователь не добавляется в результат
6) Файл users.txt имеет дубликаты логинов -> пользователь не дублируется в выходном файле

### Несколько логинов пользователей

1) Все логины есть во всех 3 файлах (txt, csv, json) -> все пользователи добавляются в результат со всеми данными

## Suite 3: Output validation tests (проверка выходного файла full_users.csv)

```
login,name,email
alice,Alice Smith,alice@example.com
bob,Bob Johnson,bob@example.com
carol,Carol Lee,carol@example.com
```

1) Формат CSV (используется , как разделитель)
2) Первая колонка: login
3) Вторая колонка: name
4) Третья колонка: email
5) Обработка негативных кейсов: понятное сообщение об ошибке
6) Нет дублирующихся логинов

# Suite 4: Execution parameters tests (параметры запуска и обработка ошибок)

```
./merge_users.sh users.txt users.json users.csv
```

1) успешный запуск скрипта с 3 валидными входными файлами (exit code 0)
2) запуск скрипта без параметров -> exit code 1 и сообщение об ошибке
3) запуск скрипта с двумя из трех параметров -> exit code 1 и сообщение об ошибке
4) запуск скрипта с некорректным filePath какого-либо из 3х входных файлов -> exit code 1 и сообщение об ошибке
